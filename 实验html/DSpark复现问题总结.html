⚡ 结论先行

自研代码犯了 两个致命错误：
① Markov bias 用了"未来词"（训练作弊）；
② 缺少 Rotary + position_ids（蒙眼猜位置）。
✅ 官方源码 第一个 epoch P0=18.56%，追平自研 15 个迭代最佳（19.6%），加速比 1.27x > 1.18x。

📖 DSpark 是什么？

  • 目标模型（Target）：大而慢，但准确（如 70B 参数）。
  • 草稿模型（Draft）：小而快，用来"猜"目标接下来会生成什么。
  • 核心思想：Draft 每次预测 连续 5 个 token，Target 一次性验证。猜对了就跳过 Target 计算，实现加速。
  • P0：Draft 第一个 token 被接受的概率，P0 越高加速越好（理想 >90%）。

🔎 差异一：Markov bias 位置错误（💀 致命）

📖 先讲概念：Markov bias 是什么？

一句话：Draft 模型在预测第 k 个词时，额外塞给它一个"小纸条"，上面写着 前一个真实 token（xk-1）的信息，帮助它更好地猜下一个词。

为什么叫 Markov：因为只依赖前一个词（一阶马尔可夫假设）。

官方：第 k 位的 bias = embedding(xk-1)（前一个词）✅
自研：第 k 位的 bias = embedding(xk)（当前词，作弊）❌

自研用了"未来信息"——猜第 k 个词时，线索应该是 前一个词，但自研用的是 第 k 个词本身（未来信息）。

  • 官方：bias 来自 xk-1（前一个真实 token） ✅
  • 自研：bias 来自 xk（当前 token） ❌

后果：训练推理条件错位，P0 崩盘。

✅ 官方做法（因果正确）
flowchart TD A1[anchor 锚点] --> B1[预测 token_0] B1 --> C1[预测 token_1] C1 --> D1[预测 token_2] B1 -.->|bias 来自 token_0| C1 C1 -.->|bias 来自 token_1| D1 D1 --> R1[训练=推理，P0 高] style R1 fill:#d4edda,stroke:#27ae60,stroke-width:2px style B1 fill:#f0faf4 style C1 fill:#f0faf4 style D1 fill:#f0faf4
bias 始终来自前一个真实 token
❌ 自研做法（作弊）
flowchart TD A2[anchor 锚点] --> B2[预测 token_0] B2 --> C2[预测 token_1] C2 --> D2[预测 token_2] B2 -.->|❌ bias 来自 token_1| C2 C2 -.->|❌ bias 来自 token_2| D2 D2 --> R2[训练作弊，推理失效，P0 低] style R2 fill:#f8d7da,stroke:#c0392b,stroke-width:2px style B2 fill:#fde8e8 style C2 fill:#fde8e8 style D2 fill:#fde8e8
bias 来自当前 token（未来信息），训练时"开卷"

📄 源码细节：Markov bias 与训练输入（官方 vs 自研）

「bias 用错位置」只是表象，它的根子在 训练时的输入构造：自研把真实未来 token 直接塞进 draft 输入，并且 attention 没有因果 mask，等于训练时“偷看答案”。

✅ 官方源码：MASK 占位 + 严格因果 + bias 用前一个真实 token

❌ 自研源码：真实未来 token 直接进输入 + 无因果 mask

⚠️ 数值上自研的 bias 变量确实取的是“上一个目标位”（prev_tokens 与 labels 相差 1），但训练时 draft 输入位置直接填真实 token、attention 又不加 mask，模型每层都能看到未来 —— 这才是“训练开卷、推理闭卷”的真正来源（迭代14 已在 train_dspark_aligned.py:184-185 改用 MASK 输入，但其它差异仍在，P0 依旧上不去）。

🔎 差异二：缺少 Rotary + position_ids（💀 严重）

📖 先讲概念：Rotary 位置编码是什么？

一句话：给每个 token 打上一个"位置标签"，告诉模型"我是第 1 个"、"我是第 5 个"。

为什么 Draft 需要它：Draft 要连续预测 5 个词，如果没有位置标签，它分不清"第 2 个"和"第 4 个"在语义上的区别，预测顺序会乱。

官方：使用 Qwen3 的 RotaryEmbedding + 显式 position_ids ✅
自研：完全没有位置信息 ❌

蒙眼猜位置——每个 draft token 的 绝对位置 至关重要。自研没有位置信息，模型完全分不清"第 1 个"和"第 5 个"的区别。

  • 官方：显式 position_ids + Rotary ✅
  • 自研：无 ❌

后果：Draft 对位置不敏感，token 顺序混乱。

✅ 官方做法
flowchart TD I1[输入: 苹果很好吃] --> P1[position_ids: 5,6,7,8,9] P1 --> D1[Draft 知道位置] D1 --> O1[准确率高] style O1 fill:#d4edda,stroke:#27ae60,stroke-width:2px style P1 fill:#f0faf4
有位置雷达，模型清楚每个 token 的绝对位置
❌ 自研做法
flowchart TD I2[输入: 苹果很好吃] --> P2[❌ 无 position_ids] P2 --> D2[Draft 分不清位置] D2 --> O2[准确率低] style O2 fill:#f8d7da,stroke:#c0392b,stroke-width:2px style P2 fill:#fde8e8
无位置信息，模型混淆不同位置的 token

📄 源码细节：位置编码（官方 vs 自研）

✅ 官方源码：显式 position_ids + Rotary 位置编码

MASK token 的 embedding 对所有位置都是同一个向量，加上没有位置编码，7 个 draft 位置在进入 attention 之前就已不可区分 —— 这正是“蒙眼猜位置”的源码真相。

🔎 差异三：缺少 Q/K Norm（⚠️ 中）

📖 先讲概念：Q/K Norm 是什么？在哪？

一句话：Q（查询）和 K（键）做点积之前，各加一层 RMSNorm（类似"音量稳压器"），让点积结果保持在合理范围，防止梯度爆炸/消失。

位置：在 每一层 Draft 的 Multi-Head Attention 内部，Q 和 K 做点积 之前 分别经过 RMSNorm。

官方：每层 Attention 都有 Q/K Norm ✅
自研：完全没有 ❌

音量没调稳——注意力机制里 Q 和 K 点积结果不稳，梯度就会爆炸或消失。官方加了 RMSNorm 来"稳压"，自研没有。

  • 官方：Q + K 经过 RMSNorm ✅
  • 自研：直接点积 ❌

后果：注意力分布不稳，训练震荡。

✅ 官方做法（有稳压）
flowchart TD Q1[Query] --> N1[RMSNorm 归一化] --> S1[点积] K1[Key] --> N2[RMSNorm 归一化] --> S1 S1 --> A1[稳定注意力] --> G1[训练平稳] style G1 fill:#d4edda,stroke:#27ae60,stroke-width:2px style N1 fill:#f0faf4 style N2 fill:#f0faf4
归一化后注意力值稳定，梯度平滑
❌ 自研做法（无稳压）
flowchart TD Q2[Query] --> S2[直接点积 ❌] K2[Key] --> S2 S2 --> A2[注意力忽大忽小] --> G2[梯度震荡] style G2 fill:#f8d7da,stroke:#c0392b,stroke-width:2px style S2 fill:#fde8e8
无归一化，点积结果不稳定，训练震荡

📄 源码细节：Q/K Norm（官方 vs 自研）

✅ 官方源码：每个 Draft 注意力层都对 Q、K 先做 RMSNorm 再点积

❌ 自研源码：三个版本的 DraftAttention 都没有 Q/K Norm

缺 Q/K Norm 单独不会致命，但会放大“无位置编码”带来的尺度问题，让训练震荡、收敛变慢。

🔎 差异四：confidence head 太简单（⚠️ 中）

📖 先讲概念：confidence head（置信度预测头）是什么？

一句话：Draft 每猜一个 token，都附上一个"信心分"，告诉 Target"我这一句有 90% 把握是对的"。Target 就按这个分数决定：直接采纳一串，还是只采纳到某一位就重新生成。

为什么需要它：投机采样的加速效果取决于"敢不敢连续采纳多个 token"。如果 Draft 没把握却硬撑，被驳回后反而更慢；confidence head 就是给"是否继续"做决策的裁判。

官方：把 hidden states（可拼接 Markov 向量）喂给 AcceptRatePredictor 预测接受率 ✅
自研：只有一个线性层，且训练目标来自实时重算的 target 分布 ❌

官方用 AcceptRatePredictor（多层 MLP），自研只有单层线性，表达能力弱。

  • 官方：多层 MLP + Markov 拼接 ✅
  • 自研：单 Linear ❌

后果：接受率预测不准。

✅ 官方做法
flowchart TD H1[hidden states] --> M1[多层 MLP] --> P1[精确预测接受率] H1 --> M2[Markov 拼接] --> M1 P1 --> O1[决策准确] style O1 fill:#d4edda,stroke:#27ae60,stroke-width:2px style M1 fill:#f0faf4
复杂模型能捕捉更多特征，预测精准
❌ 自研做法
flowchart TD H2[hidden states] --> L1[单层 Linear] --> P2[粗略预测] P2 --> O2[决策不准] style O2 fill:#f8d7da,stroke:#c0392b,stroke-width:2px style L1 fill:#fde8e8
单层线性表达能力弱，预测粗糙

📄 源码细节：confidence head（官方 vs 自研）

✅ 官方源码：输出 logits + BCEWithLogits，监督目标来自缓存的 target 分布

🔎 差异五：loss 归一化方式不同（⚠️ 低）

📖 先讲概念：loss 归一化（多卡）是什么？

一句话：训练时 loss 要除以“有效样本数”才公平。多卡训练时，每张卡分到的数据量可能不同（尤其尾部批次不满），官方先把所有卡的分母全局加起来再归一化，保证每张卡对梯度的贡献比例一致；自研只在本地卡各算各的 mean()。

什么时候有影响：单卡训练时两者完全等价（分母就是本地样本数），只有多卡且各卡样本数不平衡时才会让梯度尺度错位。

多卡训练时，官方做 全局 all_reduce 统一分母；自研各卡独立算 mean()。

  • 官方：all_reduce 全局归一化 ✅
  • 自研：本地 mean() ❌（单卡无差异）

后果：多卡训练时梯度不一致。

✅ 官方做法（多卡）
flowchart TD L1[卡1 loss] --> R[all_reduce 汇总] L2[卡2 loss] --> R L3[卡3 loss] --> R R --> U[统一分母] --> G1[梯度一致] style G1 fill:#d4edda,stroke:#27ae60,stroke-width:2px style R fill:#f0faf4
所有卡 loss 汇总后统一归一化，梯度方向一致
❌ 自研做法（多卡）
flowchart TD M1[卡1 mean] --> G2[各自梯度] --> H[方向不一致] M2[卡2 mean] --> G2 M3[卡3 mean] --> G2 style H fill:#f8d7da,stroke:#c0392b,stroke-width:2px style M1 fill:#fde8e8 style M2 fill:#fde8e8 style M3 fill:#fde8e8
各卡独立归一化，梯度方向可能互相抵消

🔎 差异六：缺少 target 缓存（⚠️ 中）

📖 先讲概念：target 缓存是什么？

一句话：Target 模型（大模型）跑一次很贵。官方在训练开始前，先把 Target 对 所有训练数据 的 hidden states 和 logits 算好存成文件（缓存）。训练 Draft 时直接读这个文件来算 TV loss。

官方：提前缓存，训练时直接读取 ✅
自研：每次迭代重新 forward Target ❌

大白话：官方是"提前抄好答案，训练时直接对答案"；自研是"每做一道题，就让老师重新做一遍，再对照答案"。

  • 官方：prepare_target_cache 提前缓存 ✅ → 快 + 目标固定
  • 自研：每次重新 forward ❌ → 慢 + 目标可能抖动（dropout 等因素）

后果：训练慢，且 TV loss 目标不精确，干扰训练。
