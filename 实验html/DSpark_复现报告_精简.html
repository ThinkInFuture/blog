第一章：论文关键点（arXiv:2607.05147）

1.1 核心思想

投机解码：草稿提议 γ 个 token，target 一次并行验证。每轮延迟 L = (T_draft + T_verify)/τ。

DSpark 解决两个瓶颈： 1. 并行草稿质量：并行草稿缺 token 依赖 → 多模态冲突 + 后缀衰减 2. 验证效率：盲目验证整块浪费批量计算

1.2 两大机制

半自回归架构： - 并行主干（DFlash 风格）：一次前向生成全部 base logits - 序列模块：加前缀依赖偏置 - Markov head：一阶转移，低秩 W1·W2（rank=256） - RNN head：循环状态累积前缀历史

置信度调度验证： - 置信度头：预测条件接受概率 c_k - STS 校准：ECE 纠正 - 硬件感知调度器：动态验证长度

1.3 训练目标

L = 0.1·L_ce + 0.9·L_tv + 1.0·L_conf
w_k = exp(-(k-1)/γ)  （position 加权）

1.4 数据与评估

  • 数据：Open-PerfectBlend 130万条，responses 由 target 重新生成，10 epochs
  • 评估：sampling temperature=1.0，accepted length

1.5 官方结果（Qwen3-4B）

  • GSM8K accepted length 6.11，加速 5.24x
  • Position 接受率：[0.93, 0.86, 0.79, 0.73, 0.67, 0.61, 0.56]

2.1 Markov Head（序列模块）

官方实现（VanillaMarkov，markov_head.py）：

class VanillaMarkov(nn.Module):
    def __init__(self, *, vocab_size, markov_rank):
        self.markov_w1 = nn.Embedding(vocab_size, markov_rank)  # 词嵌入
        self.markov_w2 = nn.Linear(markov_rank, vocab_size, bias=False)  # 投影

    def compute_step_bias(self, token_ids, hidden_states):
        # B(x_{k-1}, ·) = W1[x_{k-1}] · W2
        return self.project_bias(self.get_prev_embeddings(token_ids))

    def apply_step_logits(self, logits, *, token_ids, hidden_states):
        return logits + self.compute_step_bias(token_ids, hidden_states)

    def sample_block_tokens(self, base_logits, *, first_prev_token_ids, hidden_states, temperature=0.0):
        # 逐步采样：每步用前一个采样 token 计算 bias
        for step_idx in range(proposal_len):
            step_logits = self.apply_step_logits(base_logits[:, step_idx, :],
                                                 token_ids=prev_token_ids, ...)
            next_token_ids = sample_tokens(step_logits, temperature=temperature)
            prev_token_ids = next_token_ids

我的实现（train_dspark_aligned.py）：

# Markov head（rank=256）

self.markov_w1 = nn.Embedding(self.vocab_size, self.markov_rank)
self.markov_w2 = nn.Linear(self.markov_rank, self.vocab_size, bias=False)

def markov_bias(self, prev_tokens):
    return self.markov_w2(self.markov_w1(prev_tokens.long()))

def forward(self, draft_input_ids, target_features, prev_tokens=None):
    ...
    logits = self.lm_head(h)
    if prev_tokens is not None:
        logits = logits + self.markov_bias(prev_tokens)  # 加 bias

对比结论： - ✅ 结构一致：W1 embedding + W2 投影，低秩 rank=256 - ✅ bias 公式一致：logits + W1[x]·W2 - ⚠️ 推理方式：官方 sample_block_tokens 逐步采样（temperature 可配）；我用逐步 argmax（greedy） - ❌ 缺 Gated/RNN 变体：我只实现 vanilla，未实现 gated、rnn

2.3b Confidence Head（置信度头）[迭代12 新增]

官方实现（common.py AcceptRatePredictor）：

class AcceptRatePredictor(nn.Module):
    def __init__(self, input_dim: int):
        self.proj = nn.Linear(int(input_dim), 1)
    def forward(self, features):
        return self.proj(features).squeeze(-1)
# 输入 = [h_k; W1[x_{k-1}]]，监督目标 c* = 1 - ½||p_d - p_t||₁

我的实现（train_dspark_aligned.py，迭代12 加入）：

# Confidence head：输入 [hidden; markov_emb] -> 接受概率
self.confidence_proj = nn.Linear(self.hidden_size + self.markov_rank, 1, bias=True)

def confidence(self, hidden_states, prev_tokens):
    markov_emb = self.markov_w1(prev_tokens.long())
    feat = torch.cat([hidden_states, markov_emb], dim=-1)
    return torch.sigmoid(self.confidence_proj(feat).squeeze(-1))

对比结论： - ✅ 结构一致：Linear(input_dim,1) + sigmoid，输入 [hidden; markov_emb] - ✅ 监督目标一致：c* = 1 - ½||p_d - p_t||₁（TV 距离导出），BCE 损失 + position 加权

2.4 损失函数 [迭代12 更新：补充 confidence loss]

官方实现（loss.py）：

# 0.1·L_ce + 0.9·L_tv + 1.0·L_conf
ce_loss = -Σ w_k·log p_d(x*)           # 交叉熵
tv_loss = Σ w_k·||p_d - p_t||₁         # 分布匹配
conf_loss = -Σ w_k[c*_k log c_k + ...] # 置信度
w_k = exp(-(k-1)/γ)                    # position 加权

我的实现（train_dspark_aligned.py，迭代12 完整对齐）：

def tv_loss(draft_logits, target_logits, labels):
    draft_probs = F.softmax(draft_logits.float(), dim=-1)
    target_probs = F.softmax(target_logits.float(), dim=-1)
    tv = (draft_probs - target_probs).abs().sum(dim=-1)
    w = torch.exp(-torch.arange(gamma).float() / gamma)  # position 加权
    return (tv * w).mean()

# confidence loss（迭代12 加入）
tv_dist = (draft_probs - target_probs).abs().sum(dim=-1)
conf_target = (1.0 - 0.5 * tv_dist).clamp(0.0, 1.0)
conf_loss = F.binary_cross_entropy(conf_pred.float(), conf_target.detach(),
                                   weight=w.expand_as(conf_target)).mean()

loss = 0.1·ce_loss + 0.9·tv_loss + 1.0·conf_loss

对比结论： - ✅ CE + TV + position 加权 + confidence loss 全部对齐（0.1/0.9/1.0 权重，w_k 一致）

附录C：K2 报告补遗 v2（800截断 + 数据生成环节）

补齐 gen_k2_report.py / gen_k2_report_supp.py 中遗漏的「数据生成」环节与所有「疑似有问题」的代码点。

一、修正漏掉的"数据生成"环节

DSpark 训练数据需要两步，官方是分开的：

  1. 数据生成：target 模型给 prompt 生成回答 → 写 *_regen.jsonl
  2. 特征生成：读 *_regen.jsonl，target 前向抽 hidden → 写 cache

项目实际：❌ 没有独立的数据生成脚本。gen_k2_data.py 把两步合并，回答不落盘，无法复现某条样本的 response 内容，无法 debug。

二、800 截断疑点

scripts/gen_k2_data.py:58 的 m["content"][:800] 是从 gen_perfectblend_data.py:74 抄过来的，但 K2 prompt 比 PB 长得多（前 100 条实测 138-3193 chars，被 800 截断的有 ~60-70%）。

800 chars ≈ 200-270 tokens，正好压在 MAX_LEN=256 边界。两层截断并存且冗余。

修复建议：去掉 chars 级 800，统一按 token 数截断 prompt（保留 N 给 prompt，M 给回答）。

三、其他疑似有问题的 10 个点

  1. attention_mask 缺失（已有 warning）：gen_k2_data.py:124-127，pad=eos 时无害但脆弱
  2. 二次前向浪费算力：第一次 generate 已经算 hidden_states，又算一次完整 36 层前向
  3. generate hidden_states 取舍：output_hidden_states=True 已被 transformers 标 deprecated 风格
  4. 采样进度 4409 vs 特征目录 7801 不一致：多目录重复或 progress.json 被重置
  5. progress.json 是全局索引：若 k2_full.jsonl 被替换会失效
  6. 两套截断并存：chars 级 800 + token 级 256，冗余
  7. do_sample=True 让 cpu/gpu 训练结果不一致：CPU fp32 vs CUDA bf16 输出不同
  8. max_new_tokens=96 太小：官方 4096，96 远不够回答 K2 复杂任务
  9. anchor 边界条件：max_anchor <= start_anchor 时被跳过，语义不清晰
  10. flush 断电不安全：npz 直接写无原子 rename，崩溃时 done 与 feature 不一致

四、需要补的脚本

建议新建 scripts/regen_k2_response.py，单独生成 k2_full_regen.jsonl，让训练数据可追溯、可复现、可 debug。
