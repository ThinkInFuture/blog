DP 与 TP 与 PCP 卡位关系：输入切分和权重切分如何落到每张卡

核心关系（主流 MoE 部署 · EP 开启）：
· TP = dense 层权重切分：把 attention 投影等稠密矩阵切成 TP 份；
· PCP = prefill 上下文并行：把一条请求的输入序列切成 PCP 段，各卡并行算自己那段（只在 prefill 生效，decode 不走 PCP）；
· DP = 请求副本份数：MoE 模型里只有 dense 部分真正复制；
· EP（专家并行）：MoE 专家权重按整机池 DP × PCP × TP 切——PCP 与 DP 都进专家切分池（见「MoE 层的切分池」一节）；
· 每张卡 = 1/TP 的 dense 分片 × 1/池的专家 × 1/PCP 输入段；单副本卡数 = TP × PCP，全局总卡 = DP × TP × PCP。

MoE 层的切分池：DP × PCP × TP 一起进

例 1-3 里每卡的「专家 1/池」从哪里来。vLLM 的 fused MoE 层把三个开关压成一个切分池：专家分片按 flatten_tp = dp × pcp × tp 切；dense 的 linear 层没有 DP/PCP 逻辑，所以 dense 部分只有 TP 份，专家部分按整机池切——主流 MoE 部署（如 950DT 的 P 端 TP1×PCP8×DP1 + EP，池=8）正是这样。

MoE 层把三个开关折算成一个池。fused MoE 构建权重分片时取 flatten_tp_size = dp_size × pcp_size × tp_size（fused_moe/config.py:1123-1124），docstring 原话「Note that PCP serves the same function as DP here」（config.py:1155）；权重加载按这个池切（fused_moe/routed_experts.py:499-500）。套到例 3（DP=4 · TP=2 · PCP=4）：dense 每卡持 1/2 权重，而 MoE 的专家权重被切成 1/(4×2×4) = 1/32 份，摊在全机 32 张卡上——DP 组之间不再完全独立。

前向怎么凑齐计算。激活先跨 PCP 组 all-gather 拼成完整序列（vllm-ascend prepare_finalize.py:427-445），专家部分和跨 flatten 池 all-reduce 归约（fused_moe/moe_runner.py:451），最后 reduce_scatter 切回各 PCP 段（prepare_finalize.py:548-550）。也就是说 MoE 层的「每卡 1/32 权重」与「每卡一段输入」并不像 dense 那样各自独立，而是整池协作。

一句话结论。「PCP 会切权重」不是例外，而是 MoE 层的默认行为；只有纯 dense 模型才回到「DP 复制、PCP 只切输入」（见附录）。

TP 切的不只是权重：每个 Transformer Block 要 2 次 AllReduce

权重切分必然带来跨卡汇总。TP 把每层矩阵切给多张卡，切法成对出现：列切（切输出维度）各卡算自己那部分输出，互不相干；行切（切输入维度）每卡只能乘到一部分输入，吐出的是「部分和」，要还原完整结果必须把各卡的部分和加总——这次加总就是 AllReduce。

一个 Block 正好撞上两次行切。Attention 段：QKV 列切 → 各卡算自己那部分注意力头 → 输出投影 o_proj 行切 → AllReduce #1。MLP 段：FC1 列切 → 激活 → FC2 行切 → AllReduce #2。所以 TP 每多切一层，前向关键路径上就多了两次跨卡归约。

代码落点。vLLM 的 ColumnParallelLinear（linear.py:407）没有归约步骤；RowParallelLinear（linear.py:1510）在 forward 末尾显式做 tensor_model_parallel_all_reduce(output_parallel)（linear.py:1659-1660），条件正是 reduce_results and tp_size > 1——两次 AllReduce 的出处就在这两行。

附录：纯 dense 模型

「DP 复制、PCP 只切输入」只有在纯 dense 模型里成立。模型没有专家层时，FusedMoEParallelConfig 不参与，权重切分只有 TP 这一维（linear.py），DP 是整模型的真复制（按 TP 分片复制），PCP 纯粹切输入 —— 本文例 1-3 的「每卡 dense 完整」那行在 dense 模型里就是每卡完整权重。一旦模型有 MoE 层，DP 与 PCP 都进专家切分池，简单图例不再成立。

读图要点
· 列是输入 · 行是 dense 片：输入段颜色沿列贯穿，dense 分片颜色沿行贯穿；专家部分没有行列——它是整机一个池（图 5）。
· PCP 只作用 prefill：prefill 阶段各卡并行处理自己的输入段；decode 阶段一般走主卡，不沿用 PCP 切分。
· DP 的独立只在请求与 dense 层面成立：不同 DP 组跑不同请求、总卡数直接相乘；专家池跨 DP 组（图 5 · 表 2）。
· TP 自带归约成本：行切的 o_proj 与 FC2 每 Block 各一次 AllReduce（图 6 · 表 3），这是 TP 通信开销的来源。
