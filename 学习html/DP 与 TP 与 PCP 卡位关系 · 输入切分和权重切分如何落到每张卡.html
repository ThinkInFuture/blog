DP 与 TP 与 PCP 卡位关系：输入切分和权重切分如何落到每张卡

核心关系：
· DP = 完整模型副本的份数，每个副本独立跑请求，用来堆 QPS；
· TP = 权重切分：把权重切成 TP 份，每份常驻一组卡；
· PCP = prefill 上下文并行（prefill context parallelism）：把一条请求的输入序列切成 PCP 段，各卡并行算自己那段，切分只作用输入、不影响权重，且一般只在 prefill 阶段生效（decode 不走 PCP）；
· 一个副本内部，每张卡 = 一个权重分片 × 一段输入，单副本卡数 = TP × PCP，全局总卡 = DP × TP × PCP。

TP 切的不只是权重：每个 Transformer Block 要 2 次 AllReduce

权重切分必然带来跨卡汇总。TP 把每层矩阵切给多张卡，切法成对出现：列切（切输出维度）各卡算自己那部分输出，互不相干；行切（切输入维度）每卡只能乘到一部分输入，吐出的是「部分和」，要还原完整结果必须把各卡的部分和加总——这次加总就是 AllReduce。

一个 Block 正好撞上两次行切。Attention 段：QKV 列切 → 各卡算自己那部分注意力头 → 输出投影 o_proj 行切 → AllReduce #1。MLP 段：FC1 列切 → 激活 → FC2 行切 → AllReduce #2。所以 TP 每多切一层，前向关键路径上就多了两次跨卡归约。

代码落点。vLLM 的 ColumnParallelLinear（linear.py:407）没有归约步骤；RowParallelLinear（linear.py:1510）在 forward 末尾显式做 tensor_model_parallel_all_reduce(output_parallel)（linear.py:1659-1660），条件正是 reduce_results and tp_size > 1——两次 AllReduce 的出处就在这两行。

与本文前几节的衔接。前面例 1-3 的「每卡 = 权重片 × 输入段」只说明权重怎么摆；本节补上 TP 的另一面——行切那两处部分和必须归约，TP 的通信成本正在于此。在昇腾实现里这两次归约走 NPU 互联，TP 层数越深、卡数越多，归约在关键路径上的占比越高。

读图要点
· 列是输入，行是权重：输入段颜色沿列贯穿，权重片颜色沿行贯穿，卡的位置由行×列唯一确定。
· PCP 只作用 prefill：prefill 阶段各卡并行处理自己的输入段；decode 阶段一般走主卡，不沿用 PCP 切分。
· DP 之间完全独立：不同 DP 组跑不同请求，没有跨组的输入或权重通信，总卡数直接相乘。
· TP 自带归约成本：行切的 o_proj 与 FC2 每 Block 各一次 AllReduce（图 5 · 表 2），这是 TP 通信开销的来源。
