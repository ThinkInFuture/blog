如何用 RSI 做模型自我演进

RSI（Recursive Self-Improvement，递归自我改进）指系统改进自身能力、并用改进后的自身去产出下一代改进的闭环。这个概念早在 I. J. Good 的"智能爆炸"设想和 Schmidhuber 的 Gödel machine 中就被提出：一个足够强的系统，如果能改造自己的核心，改进会复利式放大。大模型出现之前，这只停留在思想实验层面——因为"改进自身"既没有可执行的载体，也没有客观的验收标准。

今天这两块拼图都凑齐了：可验证的任务域（代码可以跑单测、数学可以对答案）让"改进是否有效"可以被机器判定；强基座模型 + RL 后训练范式（如 GRPO）让"自己生成训练信号"成为可执行的工程。本文以一套已跑通阶段 A 的 RSI 工程实践为骨架，讲清如何用 RSI 做模型自我演进：飞轮怎么转、奖励怎么设计、验证怎么兜底、验收怎么判定，以及离真正的"递归"还差哪几步。

先统一口径：当前实现是自训练闭环（self-training loop）——同一代模型内自我产数据、自我优化。完整的 RSI 还要求跨代递归：下一代系统在上一代搭建的环境中训练，且改进本身可复利。两者不能混为一谈，对外表述请用"自训练闭环"。

一、总览飞轮：整个系统怎么转

整个系统是一个双层飞轮。内层是同一代内的自训练闭环：从种子任务和真实环境出发，模型自己生成任务、生成解题脚手架、生成解题轨迹，经过外部验证后聚合奖励，再用 GRPO 对任务生成、脚手架生成、轨迹生成三个模块做联合优化，然后评估、判断停止条件。外层是跨代递归：内层跑出的高价值数据与失败案例回流到任务池、轨迹库和验证器，环境自造与基础设施自优化产出的成果用于搭建下一代系统 S(t+1)，并验证"递归增益"是否成立——固定基准不衰减、单位算力增益不下降，递归才算成立；否则诊断修正后重新进入循环。

按 RSI 的六条判据（自训练闭环、外部验证、改进改进器、递归增益、跨代继承、环境自造）对照，当前进度是：阶段 A（自训练闭环）已跑通，阶段 B（外部验证与数据回流）部分启用，阶段 C/D/E 尚未实现但架构已预留。

二、阶段 A：任务、脚手架、轨迹三阶段联合优化

自我演进的第一步，是让模型自己生产训练信号。阶段 A 把这件事拆成三个角色：TaskGen 生成任务（控制题型、难度、新颖性），ScaffoldGen 生成解题脚手架（指令、工具、任务分解、验证器草案），TrajGen 采样 K 条解题轨迹。三者共享同一个冻结基座（Qwen3.5-4B，bf16，LoRA r=32），但各自挂独立的 LoRA 适配器。

三个角色不是并列关系，而是串行依赖：任务决定脚手架，脚手架决定轨迹。所以奖励也是串行回传的——轨迹奖励会经几何加权回传给上游的脚手架和任务阶段，让"出题人"也能从"答题人"的表现中学习。工程上三个阶段串行训练、独立 LoRA 用完即毁以防显存溢出，KL 系数显式配置（beta=0.04）防止跑偏，每阶段结束 save_model 落盘。

这套设计的意义在于：数据不再是人喂的，而是模型自己长出来的。人工标注数据总有天花板，而自产数据的规模只受算力和验证器约束。

三、奖励设计：三层乘法结构，任一趋零即归零

自训练最大的风险是模型学会"作弊"——刷高奖励指标而不真正提升能力。奖励设计是整个系统的第一道防线。这套方案对三类生成物分别定义奖励，且结构上全部采用乘法而非加法：任务奖励 = validity × difficulty × novelty；脚手架奖励 = 对齐度 × 判分保真 × 抗作弊；轨迹奖励 = 正确性 + 过程 + 格式。乘法结构的好处是任一维度趋零，总奖励即归零——模型无法靠牺牲某一维度来刷高另一维度。

几个值得展开的细节：

  • validity（有效性）是硬门：任务本身必须合法可解，才有部分分阶梯；
  • difficulty（难度）按 exp(-|pass_rate - 0.2| / 0.2) 计算——目标通过率压在 20% 附近，太简单的题没有训练价值，太难的全错也没有梯度信号；
  • novelty（新颖性）用嵌入余弦距离度量，并对"方差趋零"（任务池同质化）的场景自动上调权重，防止模型反复生成同一类任务；
  • 过程奖励不用结果倒推，而是用前缀蒙特卡洛（prefix Monte Carlo）价值估计，对推理的中间步骤给分——这直接影响模型能不能学会"一步步想"。

四、外部验证：自我演进必须踩得住的五道关卡

纯靠模型自评的奖励迟早被"黑客"。模型既是运动员又是裁判时，唯一能信任的是模型之外的物理事实：代码在沙箱里真的跑通了、单元测试真的通过了、错误解真的被测试判死了。这也是 RSI 六判据里"外部验证"被列为强判据的原因。

验证层设计成五道串联的关卡：① 规则校验（格式、类型、边界）→ ② 沙箱执行（子进程、超时、隔离）→ ③ 单元测试（参考解 + 测试用例）→ ④ 变异杀灭（对参考解做变异，错误解必须被判死，防止"弱测试"放水）→ ⑤ 奖励黑客门禁（对比代理指标与真实任务表现）。任何一关拒绝，样本进入 reject_reason 统计——这个归因非常关键：首轮分布 weak_tests=6、reference_tests=5，用来说明被拒样本到底是"出题质量问题"还是"验证器过严"，两者的修法完全不同。

所有验证结果落盘 metrics.jsonl，支持离线重算——验收时不需要重跑训练，只看日志就能复核。

五、评估与回流：隔离保护 + 双侧过滤

"自己出题自己考"最大的陷阱是评测污染：训练任务混进了评测题，分数涨了但能力没涨。这套方案用 in_benchmark 标记把固定 Benchmark（50 题）从训练池中硬隔离——每轮启动跑 assert_isolation() 硬断言，评测任务只要缺标记就拒绝开训。

评测本身也讲究统计纪律：固定 50 题、k=8 采样、temperature=0.2、种子冻结，产出带 Wilson 95% 置信区间的 Pass@1 / Pass@4——点估计会骗人，区间不会。

训练池里的样本做双侧过滤：高价值样本回流轨迹库，失败案例回流失败案例库（失败案例往往比成功更有训练价值），回流前再过一次 in_benchmark 检查做隔离保护。任务池与轨迹库因此可以随训练轮次自增，这是"数据自产"闭环的最后一环。

六、工程落地：三方分工与当前优先级

RSI 是一个长周期系统工程，单人全链路既容易盲区也容易失速。这套实践把角色拆成三方：训练方负责工程实现、5–10 轮隔离长跑、指标落盘与 bug 修复；审阅方负责代码逐段审查（奖励核、MCTS、变异杀灭是重点）、按六判据收紧定义、识别泄露与估计偏差等陷阱；项目方负责设定 Code / Agent 双线目标、裁决优先级（边缘任务修复优先于新功能）、协调单卡与沙箱资源，并守住对外口径——"自训练闭环"不等于"RSI"。

当前的最高优先级是一个具体 bug：边缘任务比例为 0——自产任务全部落在模型舒适区，难度反馈失效，训练失去梯度信号。处理顺序：训练方先跑隔离长跑冻结 baseline，审阅方核对 estimator 契约与隔离断言，项目方裁决 Code / Agent 双线的启动顺序。

七、路线图：从自训练闭环到跨代递归

按六判据把 RSI 的完整路径切成 A–F 六个阶段：A 单域三阶段联合优化（已跑通，对应判据 1/2/4 的部分）；B 数据自产 + 五层验证（部分启用，判据 4 强化）；C 环境自造（判据 1、6——模型自己给自己造 Gym 环境）；D 基础设施自优化（判据 1——"改进改进器"，优化算子、调度、缓存这些用于训练的基础设施本身）；E 跨代递归（判据 5——下一代在上一代搭建的环境中训练）；F 规模化到 7B–32B（判据 3——递归增益的最终验证）。

每个阶段都有明确的验收锚点，不允许"感觉变强了"这种模糊表述——这也是把 RSI 从叙事变成工程的关键。

八、长跑验收：四项硬指标同时达标才过关

阶段 A 是否"靠谱跑通"，由隔离版长跑（5–10 轮）的四项硬指标判定：边缘任务 ≥ 15%（自产任务要有足够的难度分布）、有效任务 ≥ 40%（验证通过率不能塌）、Pass@1 提升 ≥ 5 点（带 Wilson CI，不是点估计）、奖励方差有信号且无长度爆炸（奖励要有区分度，同时模型不能靠把回答写长来骗奖励）。任何一项不达标，按对应分支诊断修复后重新长跑——难度反馈失效查 pass_rate 估计与指令消费，有效任务不足按 reject_reason 归因，分数涨了先查奖励黑客与过拟合，奖励无信号调 KL / 课程 / 难度分布。

这套验收流程的本质是把"模型是否真的在自我演进"变成一个可证伪的工程判定，而不是玄学。

结语：边界与下一步

这套实践的诚实之处在于它清楚自己的边界：自训练闭环不等于 RSI。真正困难的部分——环境自造（阶段 C）、改进改进器（阶段 D）、跨代递归与递归增益验证（阶段 E/F）——还没有实现，但架构已经为它们预留了位置：任务池、轨迹库、验证器库、环境接口，这些回流资产就是未来跨代训练的种子。

同样值得警惕的是自训练的固有风险：奖励黑客（代理指标与真实能力脱钩）、模型坍塌（自产数据同质化导致分布收缩——novelty 权重的自适应上调正是针对它）、评测污染（隔离断言是对它的制度化防御）。RSI 能走多远，取决于验证体系的诚信度能维持多高。
