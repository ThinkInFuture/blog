MemT-1.0-Nano 把"记忆"做进了模型前向传播：在 10 个全注意力层旁边并联一条记忆通路——一块固定 shape 的记忆矩阵（存储记忆本体），读取时当"笔记本"查，写入时当"账本"擦写。这篇回答两个最容易被图糊住的问题：模型的权重到底怎么读存储记忆？上下文又是怎么压缩进存储记忆的？图 1 是双分支训练全景，图 2 单独放大读取通路，图 3 单独放大写入通路。

图 1 · MemT-1.0-Nano 双分支联合优化架构：左 Base 锚定通用能力（L_base），右 MemT 学记忆旁路（L_mem 离策略蒸馏），总损失两支相加

问题① · 权重怎么读存储记忆（图 2）

一句话读存储记忆的不是"权重"本身，而是当前 token 的隐状态：h 投影出记忆 query（q = h·W_q_mem，W_q_mem 才是权重），q 对记忆矩阵 S 做一次线性读出（read = q·S），读出值过 RMSNorm + 输出门，与同层主干注意力输出相加——这条支路叫记忆旁路。
图 2 · 读取通路：h →（可训练权重）→ q → 对记忆矩阵 S 线性读出 → RMSNorm+输出门 → 与同层主干注意力输出相加（旁路）→ FFN

三个关键点：① 读的是激活态矩阵不是权重——S 是数据（历史压缩后的"笔记"），投影矩阵 W_q_mem 才是参数；② 读出与注意力并行而非替代——记忆旁路补的是"明文上下文之外的历史"，两条输出相加后一起进 FFN；③ 读取开销恒定——不管历史多长，q·S 都是一次定长矩阵乘，256K 上下文下首 token 延迟 104-112ms，全上下文方案约 445ms。

问题② · 上下文怎么压缩进存储记忆（图 3）

一句话每轮对话结束后有个 commit 阶段：把这一轮（输入 + 回复）的隐状态投影成记忆 k/v，逐 token 走 GDN-2 更新式——先通道衰减（遗忘）、再按 key 擦旧（擦除门 b_t）、后按 value 写新（写入门 w_t）。任意长的历史就这样被"反复擦写"收敛进固定 shape 的 S。
图 3 · 写入通路：隐状态投成 k/v → ①遗忘 ②擦除 ③写入 逐 token 更新，任意长历史收敛进固定 shape 的 S

"压缩"的准确含义：不是把历史一步摘要成一段话，而是逐 token 的擦写平衡。更新式里擦除项 (I − k_t(b_t⊙k_t)ᵀ) 负责"同 key 覆盖旧记忆"（比如改期的会议时间：同一个 key 先擦旧值再写新值——加性写入做不到这一点），写入项 k_t(w_t⊙v_t)ᵀ 负责提交新内容。128K 对话的 KV cache 约 2.6 GiB，而 S 恒为约 40 MiB（66 倍），256K 时约 130 倍——倍数随长度涨，因为分母（KV）在涨。

两个工程细节：生成期间 S 是冻结只读的快照，写入只发生在每轮结束的 commit；稳定性由擦除项"只缩不放"保证，长序列不发散（消融：token 级改轮次级更新，11 项基准均分 46.97→40.98）。

训练怎么保证记忆真能用（图 1 的双分支）

图 1 左右两个分支共享主干起点：左 Base 分支权重冻结（Anchor），只算 L_base 保住通用能力；右 MemT 分支加记忆通路联合训练，损失 L_mem 用离策略蒸馏——冻结的全上下文主干当教师，学生（MemT）只看记忆状态，用教师 top-64 token 分布做前向 KL 对齐。总量 34B token（20B 继续预训练 + 14B 后训练），两阶段缺一不可（去后训练掉 10.7 分，去继续预训练掉 2.1 分）。在 11 项记忆基准上，Nano 平均 47.0，居参数化记忆方法前二；128K 历史下端到端推理约 1.86 倍加速。

机制口径：论文《MemT-1.0: Towards Memory-Native Evolution》（arXiv:2610.26825）+ HuggingFace modeling_memt.py（erase/write/forget/output 四门、commit 阶段 token 级更新）。记忆矩阵参数量以仓库 config 为准（10 层 × 16 H_kv × 256 × 256 ≈ 10.5M 元素，FP32 约 40 MiB）。
