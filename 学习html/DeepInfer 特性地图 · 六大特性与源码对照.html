1. 部署形态：E/P/D 分离 + Wide-EP

系统形态：官方架构是 Vision Encoder / Prefill / Decode 三段分离加专用存储节点——VE 单卡部署（推荐便宜卡），prefill 用普通 8 卡机，decode 用 64–128 卡超节点；TP 与 CP 暂不使用。最小高效部署单元 = 64 卡 prefill + 64 卡 decode（P:D 实际约 1:1）。

Wide-EP 的账：decode 侧 EP 拉到 64–128，把 MoE 每步的访存量摊薄到超节点互联上，官方结论"大幅降低 decode 每步 MoE 部分的显存流量，配合 EPLB 有效抬升 TPS"；代价是大 EP 一个通信域内单卡故障即整实例不可用，容错靠重启时按健康 GPU 重定 EP 大小。

2. 并行与 EPLB：数字齐全的均衡术

EPLB 机制：每 GPU 在本职专家外多持几个冗余专家（热门专家副本）；按最近 N 步负载统计，每 M 步重排专家归属，权重经 NVLink symm_mem 在组内搬移。源码落在 model_executor/eplb/ 与 environ.py 的 EPLB 组开关。

两级调度器：Prefill LB 按总上下文四桶（<16K / 16–64K / 64–256K / ≥256K）动态调配引擎数，引擎按剩余算力配额拉活、无前缀亲和；单卡内 chunk 大小不是定值——由二次成本模型 cost(q, c)（q=本步 token 数，c=已算前缀长）反解出预算内最大 q，再经 DP 组 all-reduce MIN 收齐。Decode LB 双维平衡（请求数定批大小、KV 总长定注意力成本），短请求送低并发高 KV 卡。VE LB 机器粒度随机 + 卡上最少 patch 数。总效果≈理想离线均衡的 80%。

3. DSpark：置信度调度的变长验证

问题：固定长度验证（每步验 5 个 draft token）把验证算力浪费在接受率低的 token 上。做法：Confidence Head 预测每个 draft token 的接受概率，调度时只把验证算力分给边际收益最高的前缀子集——生产配置 draft 模型一次出 5 个 token，按预测接受率排序后选使有效吞吐最大的前缀验证。

4. 异步调度：零开销批调度器

被优化的问题：decode 第 N 步原本串行跑 schedule(N) → forward(N) → sample(N) → post-process(N)，其中 post-process 前必须做一次 CPU-GPU 同步等采样结果，GPU 在 post-process(N) 与 schedule(N+1) 期间空转。做法（沿 SGLang / NanoFlow 思路）：GPU 跑 forward(N)→sample(N) 的同时，CPU 并行跑 schedule(N+1) → launch_forward(N+1) → post-process(N−1) → launch_sample(N+1)，全程无空转。默认开启，DEEPINFER_ZERO_OVERHEAD_SCHEDULING 可关；environ.py 里 ALL/ANY 两档集体 prefill 间隔（70/100 步）就是为这套异步节奏配的。源码入口 engine/llm_engine.py 与 input_metadata/prepare_tensor_input_zos.py（zos=zero-overhead scheduling）。

5. 批不变推理与结构化输出

批不变推理：同一请求在不同批组合下输出完全一致——DEEPINFER_BATCH_INVARIANT=1 开启（当前 NVIDIA only）；叠加关掉 MTP 变长并在 SamplingParams 传固定 seq_seed，得到确定性采样（同输入同参数必同输出）。源码贯穿 attention_backend.py、tilelang_ops/random_sampling.py、parallel_utils/userbuffer.py、worker/runtime_config.py。

结构化输出：约束生成符合 regex / JSON schema / EBNF。做法是编译与推理解耦——SO 编译异步跑在专用机器上（structure_output/compiler.py 编译成文法自动机），请求进引擎前取编译结果；decode 每步推进自动机、算出合法 token 集、生成 mask 施加到采样（mask.py / matcher.py / so_matcher_builder.py）。用法：SamplingParams 传 so_args={"schema_type": ..., "schema": ...}，示例 examples/_structured_output.py；缓存与超时由 XGRAMMAR 组环境变量控制（默认缓存 10 GiB、超时 20 秒）。
