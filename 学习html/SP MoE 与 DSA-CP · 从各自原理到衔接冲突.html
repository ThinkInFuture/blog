SP MoE 与 DSA-CP：从各自原理到衔接冲突

口径：GLM V1 · TP16 · prefill 一个 batch 3520 token · 每卡 SP 分片 220 行

图 1 · SP MoE：按 token 行切，切的是"序列维"

一句话：SP MoE 让每张卡只当 1/16 的"token 包工头"——只管好自己那 220 行，算完直接交给下一层，全程谁都不需要看到全量。权重不切（每卡全量权重）。

def _ascend_sp_shard_impl(x: torch.Tensor) -> torch.Tensor:
    """Pad the token axis (dim 0) to the TP multiple, then take this rank's chunk."""
    tp_size = get_tensor_model_parallel_world_size()
    tp_rank = get_tensor_model_parallel_rank()
    sp_pad = (-x.shape[0]) % tp_size          # 垫零到 16 的倍数
    if sp_pad > 0:
        x = F.pad(x, (0, 0) * (x.ndim - 1) + (0, sp_pad))
    chunk = x.shape[0] // tp_size
    out = x[tp_rank * chunk : (tp_rank + 1) * chunk]   # ← 取本卡那段：220 行
    return out.clone() if sp_pad == 0 else out

补 · token 依赖与切分边界：SP 为什么能切、attention 为什么不能裸切

先答两句：SP 切行不是为了算 KV；token 间依赖只在 attention。

1. SP 切的是 MoE/FFN 这类“逐 token 前馈层”，不是为了算 KV。这类层的关键性质是：每个 token 的计算只依赖它自己那一行——token A 选什么专家、过什么 FFN，和 token B 毫无关系（就是一堆行独立的矩阵乘 + 门控）。所以按行切完全安全：切完各卡算各的，拼回来结果分毫不差。切行的目的是省 activation 通信与显存（每卡激活从 3520 行变 220 行，MoE 层间传递量降到 1/16），跟 KV 没关系。KV 的计算和写入发生在 attention 里（wkv 投影 + 写 KV cache，图 2 第②步），不在 MoE。

2. token 之间的依赖只存在于 attention 的交互步。真正的 token 间依赖是“每个 query 要看全序列的 K/V 算加权和”——这就是为什么 attention 不能像 MoE 那样简单按行切开各算各的，也解释了图 2 为什么约定“全量进、全量出”。

3. attention 内部要拆开看：哪步独立、哪步有依赖。

attention 内部步骤token 依赖？能否直接吃 220 行分片
Q/K/V 投影（wq_a / wq_b / wkv）无——纯逐行线性变换能（这正是 #18671 分片直通的依据）
写 KV cache无——每个 token 写自己的 KV能（每卡写自己 token 段，图 4 第②步）
注意力交互（Q·K 加权和）有——每个 query 要读全序列 KV不能裸切，需要专门机制
o_proj无——逐行能

4. 真正的交互步，DSA-CP 怎么化解。解法是：KV 分段存储 + 全局编址跨段读——每卡存自己 token 段的 KV（省显存），indexer 选中的块通过全局 block table 跨段访问（token 依赖在这里被满足）；算完再用 A2A + RS 归位（图 4 协同❶❷）。另外注意 softmax 是按 head 独立的（不同 head 互不相关），所以 head 维切（TP）也是安全的。

一句话：能按行切的地方（MoE/FFN/投影/写 KV——逐 token 独立）就切，省通信；不能切的地方（注意力交互——全序列依赖）用“KV 分段存 + 全局读 + 算完归位”来化解。SP 管“独立的部分”，DSA-CP 管“有依赖的部分”——两个特性各管一段，这才是它们能同开、也才会同开时打架的根本原因。

图 2 · DSA-CP attention：按 head 切，token 维必须全量

一句话：DSA-CP 让每张卡当 1/16 的"head 包工头"——但 head 的计算必须对着全部 token 做，所以它的门禁是"全量进、全量出"。

def restore_tp_heads(output, tp_group):
    """Exchange [local tokens, all heads] for [all tokens, local heads]."""
    if tp_group.world_size == 1:
        return output

            .permute(1, 0, 2, 3).contiguous().view(-1, local_heads, width))

def _ascend_sp_reduce_scatter_impl(x: torch.Tensor) -> torch.Tensor:
    """Pad rows to the TP multiple, then reduce-scatter across TP ranks."""
    tp_size = get_tensor_model_parallel_world_size()
    sp_pad = (-x.shape[0]) % tp_size
    if sp_pad > 0:                      # 3520 不整除时垫零
        pad_shape = [sp_pad, x.shape[1]]
        x = torch.cat([x, x.new_zeros(pad_shape)], dim=0)
    output = _custom_collective("custom_reduce_scatter", x)
    if output is not None:
        return output
    return tensor_model_parallel_reduce_scatter(x, 0)   # 全量 → 本卡 220 行
