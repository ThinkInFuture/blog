🔄 从架构到原理
了解了 KDA 在 Transformer 中的位置后，接下来深入数学原理。 KDA 的核心是将注意力计算转化为状态更新问题， 通过固定大小的隐状态压缩历史信息，实现 O(N) 复杂度。
1. 什么是 KDA 概述

KDA (Key-Dependent Attention) 是一种基于线性注意力和 Delta Rule 的高效推理算子。 它通过将标准注意力的复杂度从 O(N²) 降低到 O(N)， 实现了对长序列的高效处理，同时保持了与标准注意力相当的表达能力。

KDA 的核心思想是：将注意力计算转化为状态更新问题，通过维护一个固定大小的隐状态 (h-state)， 实现对序列信息的压缩存储，从而避免了标准注意力中需要存储完整 KV Cache 的问题。

📊 标准注意力 (Softmax Attention)

复杂度：O(N² · D) 时间 + O(N²) 空间
公式：O = softmax(QKT · scale) · V
特点：需要存储完整 N×N 注意力矩阵，KV Cache 线性增长

📊 KDA (Key-Dependent Attention)

复杂度：O(N · D²) 时间 + O(D²) 空间
公式：ht = ht-1 · exp(gt) + vt · ktT，Ot = ht · qt
特点：固定大小状态，KV Cache 恒定不变

每层每token存储 K+V = 2 × 32 × 128 × 2bytes(FP16) = 16 KB/token

❌ 核心误区澄清

误区1：训练阶段就把文本预先压缩成S存进模型权重。
事实：训练不学具体文本内容，只学记忆策略；S无论训练还是推理都是临时中间变量。

误区2：KDA是推理时对普通Transformer KV做后处理压缩。
事实：不是后处理；整套门控网络必须预训练就嵌入模型架构。

误区3：α和β是固定超参数。
事实：αt和βt每个token都不一样，由输入特征经过可学习网络动态生成（由 fused_gdn_gating 计算）。

🔗 从原理到公式
理解了 KDA 的核心思想后，接下来用数学公式精确描述状态更新过程。 KDA 的数学本质是线性注意力的递推形式， 通过门控因子控制历史信息的衰减。
2. 数学公式推导 理论基础

KDA 基于线性注意力理论，通过将 softmax(QKT)V 分解为递推形式实现高效计算。

标准注意力： O = softmax(QKT / √dk) · V
KDA 状态更新： ht = ht-1 · exp(gt) + βt · vt · ktT
KDA 输出： ot = ht · qt / √dk
图 3 KDA 状态更新流程
flowchart LR A["h_{t-1}

门控衰减"] C["v_t · k_t^T
新信息注入"] --> D["+ 融合"] B --> D D --> E["h_t
更新状态"] E --> F["× q_t
输出计算"] F --> G["o_t
当前输出"]
💡 关键变量说明

• gt：门控衰减因子，控制历史信息的保留程度。gt < 0 时衰减，gt = 0 时无衰减
• βt：Beta 系数，控制新信息的注入强度
• ht：隐状态矩阵，形状 [V, K]，压缩存储历史信息
• qt, kt, vt：Query, Key, Value 向量
🚀 Chunk-KDA 的数学技巧
为了避免逐 token 递推的串行性，Chunk-KDA 将序列分成固定大小的块 (chunk_size=64)， 块内使用矩阵运算并行计算，块间使用状态传递。 核心公式：A = I + K·KT，w = (I + A)-1 · K·β
3. KDA 完整算法流程 核心流程

KDA 的完整前向传播分为两个路径：Chunk-KDA（分块并行）和 Fused Recurrent KDA（循环融合）。

1累积门控和 (Chunk Local Cumsum)
将逐 token 的门控值 gt 转换为块内累积和，用于后续的矩阵指数计算。
g = chunk_local_cumsum(g, chunk_size=64) * RCP_LN2
其中 RCP_LN2 = 1/ln(2)，用于将自然对数底转换为以 2 为底的指数。
2计算 K·K^T 和 Q·K^T 矩阵
并行计算两个关键矩阵：
• A[i,j] = Σ_k β[k] · K[i,k] · K[j,k] · exp2(g[i] - g[j]) (块内 K·K^T)
• Aqk[i,j] = Σ_k Q[i,k] · K[j,k] · exp2(g[i] - g[j]) · scale (块内 Q·K^T)
3求解下三角矩阵逆 (Solve Tril)
计算 (I + A)-1，其中 A 是严格下三角矩阵。
使用分块求逆策略：16×16 → 32×32 → 64×64，通过 Triton 并行 kernel 实现。
4重计算 w 和 u
根据求逆结果计算权重矩阵：
• w = A_inv · K · β (用于后续 h-state 更新)
• u = A_inv · V · β (用于后续输出计算)
5计算 h-state (隐状态)
使用 Chunk Gated Delta Rule 更新隐状态：
h = chunk_gated_delta_rule_fwd_h_kda(k, w, u, gk)
支持初始状态 h0 和最终状态 ht 的保存/加载。
6计算最终输出
结合隐状态和块内注意力计算输出：
o = q · h + Aqk · V
第一项来自块间状态传递，第二项来自块内并行计算。

# kda.py - Chunk-KDA 入口函数
def chunk_kda(q, k, v, g, beta, scale=None, initial_state=None, ...):
    if scale is None:
        scale = k.shape[-1] ** -0.5

    # 可选的 L2 归一化
    if use_qk_l2norm_in_kernel:
        q = l2norm_fwd(q.contiguous(), use_tiled_kernel=True)
        k = l2norm_fwd(k.contiguous(), use_tiled_kernel=True)

    o, final_state = chunk_kda_fwd(
        q=q, k=k, v=v.contiguous(), g=g.contiguous(),
        beta=beta.contiguous(), scale=scale, ...)
    return o, final_state
# kda.py - 分块前向传播核心逻辑
def chunk_kda_fwd(q, k, v, g, beta, scale, initial_state, ...):
    chunk_size = FLA_CHUNK_SIZE  # 默认 64
    # Step 1: 累积门控和
    g = chunk_local_cumsum(g, chunk_size=chunk_size, ...)
    g = g * RCP_LN2

    # Step 2: 计算 K·K^T 和 Q·K^T 矩阵
    A, Aqk = chunk_kda_scaled_dot_kkt_fwd(q=q, k=k, gk=g, beta=beta, ...)

    # Step 3: 求解下三角矩阵逆
    A = solve_tril_kda(A=A, ...)

    # Step 4: 重计算 w 和 u
    w, u, _, kg = recompute_w_u_fwd(k=k, v=v, beta=beta, A=A, gk=g, ...)

    # Step 5: 计算 h-state 隐状态
    h, v_new, final_state = chunk_gated_delta_rule_fwd_h_kda(
        k=kg, w=w, u=u, gk=g, initial_state=initial_state, ...)

    # Step 6: 计算最终输出
    o = chunk_gla_fwd_o_gk(q=q, v=v_new, g=g, A=Aqk, h=h, scale=scale, ...)
    return o, final_state
# fused_recurrent_kda.py - 逐 token 循环递推
@triton.jit(do_not_specialize=["N", "T"])
def fused_recurrent_gated_delta_rule_fwd_kernel(q, k, v, g, beta, o, ...):
    # 初始化隐状态
    b_h = tl.zeros([BV, BK], dtype=tl.float32)
    if USE_INITIAL_STATE:
        b_h += tl.load(p_h0, mask=mask_h, other=0).to(tl.float32)

    # 主循环：逐 token 递推
    for i_t in range(0, T):
        b_q = tl.load(p_q, ...).to(tl.float32)
        b_k = tl.load(p_k, ...).to(tl.float32)
        b_v = tl.load(p_v, ...).to(tl.float32)

        # KDA 特殊处理：向量门控
        if IS_KDA:
            b_gk = tl.load(p_gk).to(tl.float32)
            b_h *= tl.exp(b_gk[None, :])  # 门控衰减

        # Delta Rule 更新
        b_v -= tl.sum(b_h * b_k[None, :], 1)  # 残差计算
        b_v *= b_beta
        b_h += b_v[:, None] * b_k[None, :]     # 状态更新
        b_o = tl.sum(b_h * b_q[None, :], 1)    # 输出计算
        tl.store(p_o, b_o.to(p_o.dtype.element_ty), mask=mask_v)
# solve_tril.py - 下三角矩阵求逆
@triton.jit(do_not_specialize=["T"])
def solve_tril_16x16_kernel_kda(A, Ai, cu_seqlens, chunk_indices, T, H, BT):
    # 加载 16x16 子块
    b_A = tl.load(p_A, boundary_check=(0, 1)).to(tl.float32)
    b_A = -tl.where(m_A, b_A, 0)  # 取严格下三角部分

    # 迭代求解逆矩阵
    for i in range(2, min(16, T - i_t * 16)):
        b_a = -tl.load(A + (i_t * 16 + i) * H * BT + o_i + offset)
        b_a = b_a + tl.sum(b_a[:, None] * b_A, 0)
        b_A = tl.where((o_i == i)[:, None], b_a, b_A)

    b_A += m_I  # 加上单位矩阵
    tl.store(p_Ai, b_A.to(...))

💡 为什么选择 Triton 而不是 CUDA？

• 开发效率：KDA 涉及多个复杂 kernel（矩阵求逆、门控计算等），Triton 显著降低开发难度
• 自动调优：KDA 的性能高度依赖块大小和 warp 配置，Triton 自动搜索最优参数
• 可移植性：vllm-ascend 需要支持 NPU，Triton 的多后端支持是关键优势
• 可维护性：相比 CUDA C++，Triton 代码更易理解和修改
💡 为什么使用 [V, K] 状态布局而不是 [K, V]？

• 内存访问模式：KDA 的核心操作是 h · q 和 k · v，[V, K] 布局使这些操作在内存中连续
• 向量化友好：K 维度通常较大（64-256），按 K 维度切分便于 SIMD 并行
• 与 FLA 对齐：保持与 flash-linear-attention 库的兼容性
💡 为什么 chunk_size 固定为 64？

• 硬件对齐：64 是 GPU warp size 的整数倍，便于线程分配
• 内存效率：64-token 块的 KV 数据刚好适合 Shared Memory 容量
• 并行度：64 提供足够的并行度，同时避免过度分块带来的开销
• 实验验证：64 是性能和精度的最佳平衡点
⚠️ 已知限制

• 当前仅支持 head dimension K ≤ 256
• NK > 1（K 维度分块）尚未支持
• 变长序列需要提前准备 chunk_indices
• 精度在某些边界情况下可能略有损失

核心要点回顾

1. KDA 是什么：基于线性注意力的高效推理算子，通过固定大小的隐状态替代标准注意力的 KV Cache

2. 核心算法：状态更新 ht = ht-1 · exp(gt) + β · vt · ktT，输出 ot = ht · qt

3. 两条执行路径：Chunk-KDA（分块并行，适合长序列）+ Fused Recurrent（循环递推，适合短序列）

4. Triton 协同：自动调优、内存管理、硬件抽象，让 KDA 专注于算法逻辑

5. 工程价值：内存恒定、开发高效、性能优异、可移植性强
