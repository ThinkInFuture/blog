2. 问题：布局来回倒腾（改动前）

先理清三方角色，关键是看懂 SP 怎么切。TP=16 的组里，3504 个 token（3500 的 prompt 对齐到 16 的倍数，多出的 4 个是 padding）按连续段横向切开——每卡分到 219 个，这就是模型层（DecoderLayer）手里的本地 token 分片。MoE / MLP 天然可切：各卡算各自那 219 个 token 的分片就行，谁也不需要别人的。DSA-CP attention 同样按 token 切卡：每卡只对自己那 219 个 token 的 Q 做注意力，缺的 KV 跨卡定点去取（③）。按理说模型层和 attention 拿的都是分片、布局本该一致，但原实现里对不上——老约定认为「attention 必须在全量 token 上算」，于是有了下面的 ①②④（这张切法的全貌见本节末的图 3）。

图 2 左侧是业务主线（与并行无关的算子链），右侧是并行框架挂上去的通信步骤，本 PR 只动右侧。原路径的问题：框架在 LN→注意力之间先 ① AllGather 聚成全局（[1,219,8192] → [1,3504,8192]）、attention 入口 _prepare_native_hidden_states 又 ② 切回本地段，算完 O 投影输出全局布局、框架再 ④ ReduceScatter 收回——①②④ 全是无用功，每层都来一遍；③ 取命中 KV 是 DSA-CP 本职通信。

图 2 · 改动前：左＝业务主线，右＝框架线；①②④ 为冗余通信、③ 为 DSA-CP 本职

3. 核心思路：本地分片贯穿三个边界

PR 立了一条布局契约。DSA-CP attention 后端声明 supports_sequence_parallel_input = True，含义是"我收本地分片，还你本地分片"。对照图 4（业务骨架与图 2 完全一致）：①② 两处冗余直接省掉；② 的防错位职责由新增的 ⑤ 输入校验 + padding 清零（纯本地操作）接替；④ 的归约职责并入 attention 内部的 ⑥ all-to-all + 单次 reduce-scatter；③ 本职通信原样保留。这样三个边界（DecoderLayer ↔ MLA 包装层 ↔ DSA-CP attention）看到的是同一份连续 TP token 分片。

图 4 · 改动后：业务主线一个框都没动；只动框架线——①②④ 省掉、⑤ 新增、⑥ 变化、③ 不变

3.1 为什么 ①② 能省

因为这是一对互逆操作。① AllGather 的存在理由，是上游 SP 的老约定——"attention 必须在全量 token 上算"，所以每层都要把每卡 [1,219,8192] 聚成全局 [1,3504,8192]。但 DSA-CP 的注意力天生按 token 分片算：每张卡只算自己那 219 个 token 的 Q 行，从来不需要别的卡上的 token；它唯一要的跨卡数据是命中的 KV 块，而那部分它自己通过 ③ 去拉。于是 ① 聚出来的全局 token，唯一的消费者就是紧跟着的 ②（再切回本地段）——聚了又切，切完就扔，两步互相抵消，每层每批次白付一次 AllGather 通信加两次布局整理。

3.2 为什么 ④ 能省

因为它的活儿已经有人干了。跨卡归约（把各卡的部分和加起来）这件事必须做、且只能做一次：改动后由 ⑥ 在 attention 内部完成——all_to_all 换完 head 后，数据正好是"每卡一段 token 的部分和"，紧接着一次 reduce_scatter 同时完成求和和按卡散射，一步到位。模型层原来那个 ④ 如果保留，要么重复归约（结果就错了），要么得先把数据倒腾回旧布局再散一次（通信翻倍）。所以它不是简单删掉，而是职责移进了唯一正确的位置。至于正确性：⑤ 的边界校验保证布局不可能悄悄错（错就当场抛错），FP16 的 scale 放在归约前乘，与上游语义逐位对齐——4.6 节的单测验证了新旧路径结果一致。

4. 从你认识的 attention 代码出发

先对齐地基。下面这份就是你认识的 attention 推理实现——矩阵乘、RoPE、KV Cache、softmax，十来行（GQA + KV Cache 的典型写法，batch 维省略）。本章把这份代码在 vllm-ascend 里的完成过程画成三张图：目录介绍图 → 完成流水线图 → PR 对照流水线图，每张图配一段讲解。先说结论：attention 的数学一行没动；"那一堆"其实是两样东西——你这份代码在框架里的原样出现，加上为了在 16 张卡上跑起来、在它周围加的通信与选址。

# 你认识的 attention（推理版，等价于典型的 GQA+KVCache 教程实现）
def forward(x, is_prefill):                            # x: [1, seq, hidden]
    q = x @ wq                                         # L1  Q 投影
    k = x @ wk;  v = x @ wv                            # L2  K/V 投影
    q = rope(q, pos);  k = rope(k, pos)                # L3  RoPE，只转 Q/K
    k_cache = k if is_prefill else cat(k_cache, k)        # L4  KV Cache：整条历史拼在本卡
    v_cache = v if is_prefill else cat(v_cache, v)
    k_full = k_cache.repeat_interleave(4, dim=1)       # L5  GQA：2 组 KV 复用给 8 个 Q 头
    scores = q @ k_full.transpose(-1,-2) / sqrt(dk)    # L6  打分——隐含假设：全量历史都在本卡
    if is_prefill: scores = causal_mask(scores)        # L7  因果遮罩
    w = softmax(scores, dim=-1)                        # L8  归一化
    out = w @ v_full                                   # L9  加权求和
    return out @ wo                                    # L10 输出投影

4.2 开了 SP + DSA-CP，原本的跑法出了问题

你的 L6 之所以写得那么短，是因为 L4 已经把全量历史 KV cat 进了同一张卡——"所有 token 的 KV 我都拿得到"是单卡默认成立的隐含假设。16 卡把 token 切成 16 段后，每张卡只分到 219 个 token，这个假设碎了。上游 vLLM 的解法很直接：每层先把 token 聚回全量，让你的 attention 照旧在全量上跑，算完再散回去——这就是第 2 章的 ① 和 ④（上游 deepseek_v2.py:1315，有删节）：

# 上游每层都在你的十行外面套了这两行（有删节）
if input_is_sequence_parallel:
    hidden = tensor_model_parallel_all_gather(hidden, 0)   # ① 219 → 3504：把假设"买"回来，每层白付一次
hidden = self.self_attn(positions, hidden, ...)            # ← 你的 L1~L10 在这里面，照旧全量跑
...
hidden = tensor_model_parallel_reduce_scatter(hidden, 0)   # ④ 3504 → 219：再把假设"退"回去

更亏的是 L4：DSA-CP 的注意力本来就要跨卡取命中的 KV 块（③），于是 ① 聚出来的全量 token 转头又被切回本地段（②）——聚了又切，切完就扔，每层每批都来一遍。这就是第 2 章图 2 的灰块；问题不在你的十行数学，在"喂给它的数据布局"来回倒腾。

检测技巧：程序怎么知道"输入已经是分片"？ 对比两个长度——positions 是全量长度（3504，每个 token 的位置编号都要有），hidden_states 是本卡分片长度（219）。形状对不上，就说明输入已被切成 SP 分片。不需要任何额外开关，一个 shape 比较就够了。

4.3 这次 PR：拆掉聚散，分片直通

PR 的模型层改成：分片直接进 attention，你的十行在分片上原样跑：

# PR 新增：vllm_ascend/models/deepseek_mtp.py
class AscendDSACPDecoderLayer(DeepseekV2DecoderLayer):
    def forward(self, positions, hidden_states, residual, llama_4_scaling=None):
        input_is_sequence_parallel = (self.use_sequence_parallel_moe
                                      and residual is not None
                                      and hidden_states.shape[0] != positions.shape[0])
        # 回退三条件：不是分片 / 带缩放的特殊批 / attention 契约不支持 → 原样走 4.2 的上游老路
        if (not input_is_sequence_parallel
                or llama_4_scaling is not None
                or not self.self_attn.mla_attn.supports_sequence_parallel_input):
            return super().forward(positions, hidden_states, residual, llama_4_scaling)

        hidden_states, residual = self.input_layernorm(hidden_states, residual)
        output_scale = 1.0 / self.routed_scaling_factor if hidden_states.dtype == torch.float16 else 1.0
        hidden_states = self.self_attn.mla_attn.forward_sequence_parallel(
            positions, hidden_states, output_scale=output_scale)   # 分片直进，无① 无④
        if hidden_states.dtype == torch.float16 and self.layer_idx == 0:
            residual *= 1.0 / self.routed_scaling_factor           # FP16 防溢出：第 0 层 residual 同步缩放
        hidden_states, residual = self.post_attention_layernorm(hidden_states, residual)
        hidden_states = self.mlp(hidden_states, already_sequence_parallel=True)
        return hidden_states, residual

这张图就是整个 PR。左列是原本（开了 SP+DSA-CP 的跑法），中列是 PR 的做法，逐行对着看。

改后 · AscendDSACPDecoderLayer（PR 新增）
class AscendDSACPDecoderLayer(DeepseekV2DecoderLayer):
    def forward(self, positions, hidden_states, residual, llama_4_scaling=None):
        # 判定输入是否已是"本地 token 分片"：SP MoE 开启 + residual 存在
        # + 本地 token 数 != 全局位置数（分片的典型特征）
        input_is_sequence_parallel = (
            self.use_sequence_parallel_moe and residual is not None
            and hidden_states.shape[0] != positions.shape[0]
        )
        # 首层 replicated 输入 / 不支持的投影契约 → 原样走上游，行为不变
        if (not input_is_sequence_parallel
                or llama_4_scaling is not None
                or not self.self_attn.mla_attn.supports_sequence_parallel_input):
            return super().forward(positions, hidden_states, residual, llama_4_scaling)

        # 直通链（图2）：省掉 ①④，全程无 AllGather / ReduceScatter
        hidden_states, residual = self.input_layernorm(hidden_states, residual)
        # FP16 防溢出：把 routed_scaling 缩放交给 attention 在 TP 归约"前"做
        output_scale = 1.0 / self.routed_scaling_factor if hidden_states.dtype == torch.float16 else 1.0
        # 收分片、还分片（走 4.3 的新入口）：①④ 在此省掉，归约见 5.3 的 ⑥
        hidden_states = self.self_attn.mla_attn.forward_sequence_parallel(
            positions, hidden_states, output_scale=output_scale)
        # FP16 且第 0 层：residual 同步缩放，逐位对齐上游 overflow 保护
        if hidden_states.dtype == torch.float16 and self.layer_idx == 0:
            residual *= 1.0 / self.routed_scaling_factor
        hidden_states, residual = self.post_attention_layernorm(hidden_states, residual)
        # 告诉 MLP "输入已是 SP 分片"，MLP 不再做布局整理
        hidden_states = self.mlp(hidden_states, already_sequence_parallel=True)
        return hidden_states, residual

def _prepare_sequence_parallel_hidden_states(self, hidden_states, attn_metadata):
    context = attn_metadata.dsa_cp_context
    tp_group = get_tp_group()
    local_tokens = hidden_states.shape[0]
    expected_start = tp_group.rank_in_group * local_tokens
    # ⑤ 新增（接替图2-② 的位置）：校验"本 rank 那段"，不一致立刻抛错（防静默错位）
    if (context.num_tokens != attn_metadata.num_input_tokens
            or context.num_tokens_pad != local_tokens * self.tp_size
            or context.local_start != expected_start
            or context.local_end_with_pad != expected_start + local_tokens):
        raise RuntimeError("SFA DSA-CP input does not match its sequence-parallel shard: ...")
    # Graph/DP 的 padding 区清零；先 clone 再清，避免污染 residual 的共享存储
    valid_tokens = max(0, min(local_tokens, context.num_tokens - context.local_start))
    if valid_tokens < local_tokens:
        hidden_states = hidden_states.clone()
        hidden_states[valid_tokens:].zero_()
    return hidden_states

5.3 输出收口 o_proj：路 A 全权重直算，路 B all-to-all + 单次 RS

改后 · _finalize_sequence_parallel_o_proj（PR 新增；对照图 7）
def _finalize_sequence_parallel_o_proj(self, attn_output, output, gather_full_o_proj,
                                       attn_metadata, output_scale):
    if gather_full_o_proj:
        # 路 A：full head + full weight —— 直接算出完整本地 token，零集合通信
        with self._use_full_o_proj_weights():
            output.copy_(self._apply_o_proj_full_weight(attn_output))
        if output_scale != 1.0:
            output.mul_(output_scale)
    else:
        # 路 B（⑥，常规 TP head 分片）：attn_output 是 [本地token, 全head]，
        # view 成 [本地token, tp, head/tp] 后 permute，使 tp 维落到最前；
        # all_to_all 后变成 [全token, 本地head] —— 每张卡拿到全部 token 的自己的 head
        send = (attn_output.view(-1, self.tp_size, self.num_heads * self.v_head_dim)
                .permute(1, 0, 2).reshape(-1, self.num_heads * self.v_head_dim))
        sharded_output = torch.empty_like(send)
        tp_group = get_tp_group()
        torch.distributed.all_to_all_single(sharded_output, send, group=tp_group.device_group)
        projected_output = self.o_proj(sharded_output)[0]      # 行并行：结果未归约
        if output_scale != 1.0:
            projected_output.mul_(output_scale)                # FP16：归约"前"缩放
        # ⑥ 单次 reduce_scatter = 归约 + 散射 → 本地分片（图2-④ 在此消失）
        torch.distributed.reduce_scatter_tensor(output, projected_output.contiguous(),
                                                group=tp_group.device_group)
    context = attn_metadata.dsa_cp_context
    valid_tokens = max(0, min(output.shape[0], context.num_tokens - context.local_start))
    if valid_tokens < output.shape[0]:
        output[valid_tokens:].zero_()                          # 尾部 padding 清零
    return output

6. 与我们排查问题的关系（重点）

这个 PR 测的就是我们的场景 PR 描述里的硬件测量环境：GLM-5.1 W8A8C8、MTP=3、两台 A3、TP=16 DP=2、V1 runner、SP/DSA-CP、max-num-seqs=12、max-num-batched-tokens=8192、chunked prefill、FULL_DECODE_ONLY，压测命令就是 aisbench_test.py --input_len 3500 --output_len 1500 --data_num 32 --concurrency 8 --request_rate 0 —— 与我们 135/136 双机的口径完全相同。

它优化的正是 SP + DSA-CP 路径上的冗余通信，作用点在 prefill/decode 混合批次的每一层。我们之前测得：enable_prefill_mc2 无收益（TTFT 739→753-768 持平），1009 相对 0815 的 TTFT 差距锁定在 DispatchFFNCombine kernel 回退——而这个 PR 是另一条独立的优化轴（省模型层与 attention 边界的 AG/RS），两者不冲突，理论上可叠加。

PR 报告的单次候选测量：TTFT 均值 529.3ms、TPOT 21.4ms、输出吞吐 348.7 tokens/s、零 KV 抢占；GSM8K 4-shot 全量 1319 题 97.57%。

注意两点：① PR 自己声明这是"单次候选测量，非受控对比"，不能直接跟我们 739-768ms 的数比（版本线、镜像都不同）；② GSM8K 也无基线对照。但 TTFT 529 这个量级至少说明该路径优化后没有明显劣化。

7. 收益、风险与待验证

收益 符合条件的 GLM V1 SP/DSA-CP 批次：每层省 2 次全量激活的集合通信 + 2 次布局整理；混合 prefill/decode 批次（我们 3.5K+1.5K、cc8 正是这种）受益最直接。无需新配置项，条件满足自动生效。
安全性设计 能力探测四条件不满足即回退；布局 metadata 不一致抛错且不通信；DCP / V2 / PP / 其他模型完全不动；FP16 缩放语义逐位对齐上游并有单测。
待验证 PR 自述：新增单测尚未运行；release-port 头未在 NPU 上复跑；format.sh ci 因本地缺 pre-commit 未完成；其他模型 / 并行 / dtype 组合未验证。当前为 draft。
对我们的行动建议 这个 PR 直接打在我们环境（vllm-ascend 0.30.0 线 + SP/DSA-CP）的痛点上。值得：
  • 跟进 review 进展与 CI 结果；
  • 若合入，在我们环境做一轮同口径 aisbench + profiling，对比 attention 前后通信 kernel（AllGather/ReduceScatter 占比）与 TTFT 变化——正好复用我们已固化的短窗口 profiling 姿势；
  • 它与 DispatchFFNCombine kernel 回退是两个独立问题，TTFT 差距的根因结论不受影响。
