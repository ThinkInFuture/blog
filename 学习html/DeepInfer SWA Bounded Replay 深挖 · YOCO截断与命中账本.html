DeepInfer SWA Bounded Replay 深挖：YOCO 截断的两模式与命中账本

deepseek-ai/DeepInfer @ 774ce24 yoco.py 逐字段精读 + Q&A 账本核对 2026-10-21 发布 · 前置阅读：站内 V4.1-Flash 架构文章

怎么读：SWA bounded replay 是 DeepInfer 里最"懂 V4.1-Flash 架构"的一个特性——它利用 CED/YOCO 的结构，把 decoder 侧 prefill 计算近乎砍半。本篇从架构账本讲到源码字段：为什么可行、mask/compact 两种模式差在哪、命中规则怎么算、SWA state 存了什么。

1. 为什么需要：CED 架构下 decoder prefill 的账

前置架构（站内 V4.1 系列已展开）：V4.1-Flash 把 40 层拆成 20 层编码器 + 20 层解码器；CED 让解码器的块 KV（全局稀疏 KV）直接从编码器末层隐藏态投影得到——prefill 阶段解码器的块 KV 不用算。剩下的成本：每个解码器层的 SWA KV（滑窗注意力缓存）仍需逐层计算，而 YOCO 语义下解码器层消费 KV 时不重算。

精确重建的价（官方 Q&A 原数字）：要精确重建解码器 SWA KV，得把最后 2,560 个 token 跑完 20 个解码器层；bounded replay 的选择是——每个 prefill 只在解码器层重算最近 128 个 token，注意力窗口截断到重算段内（位置 i 的 query 只看 max(s, i−127) 到 i），得到一份近似 SWA KV。结果只供本次 decode 用、不进前缀缓存。这笔账的效果：总 prefill 计算量近乎减半，重算成本与上下文长度、层数都无关（常数）。

2. 两模式：mask 与 compact

源码主战场：deepinfer/model_executor/input_metadata/yoco.py（182 行，YocoMetadataMixin）。文件头 docstring 写明：字段由 C++ prepare_prompt_v4 按截断模式二选一产出，两模式的 SWA 可见域同式（C++ 共用 yoco_swa_visibility），因此attention 数值在保留区间内一致——两模式是性能取舍不是精度取舍：

V4.1 默认参数（README）：mode=compact、KEEP_TOKENS=140。约束式：KEEP_TOKENS ≥ window_size(128) + MAX_BACKTRACKING_TOKENS——保留的末尾必须罩住 SWA 窗口加投机解码的最大回退长度；MAX_BACKTRACKING_TOKENS 的默认下限正是 USE_NEXTN_DECODE+1（draft 5 → 至少 6），与 DSpark 特性咬合。

compact 布局的字段全家（yoco.py 逐字段）：query_indices（full→compact 的 gather 正映射）、cu_seqlens_q（cumsum(keep_len) 边界）、positions、swa_index_pivots（[total_q_c, 4] int32 可见域）、ks/ke（按稀疏层压缩比分键的 compact 版）、kv_ca_index_offset_len（按稠密压缩比分键）、slot_mapping_store_swa（占位 token 显式 −1 不写 ring）、cp_mirror_len 与 cp_contrib_pad_len（CP 边界重分布，CP==1 时为 None）。

3. 命中账本：两段缓存怎么配合

总原则（官方 Q&A）：命中长度由块 KV 缓存决定；最后一个块要不要重算由 SWA KV 缓存决定——SWA 缺失就退一块重算。具体三步：上限先卡死——长为 L 的输入，YOCO 截断要求下最大命中 ≤ L−134（128 窗 + 6 回退）；查块 KV 得 L1（128 的整数倍）；再看 L1−128 到 L1 区间内有没有 SWA KV，有则命中 L1，没有则 L1−128（128 是重算窗口）。

编码器侧也有 replay：前缀缓存命中后，编码器只重算命中前缀的最近 128 token 并与未命中后缀一起前向——重算段只重建 SWA KV，块 KV 原样复用、既不重算也不覆写。编码器侧 SWA KV 缺失时同样退一块。

4. SWA state 存储：算清一笔账

StateBlock 两区：每序列占一个定长槽，按"是否需要持久"分两区——[stored 区：SWA] 与 [dropped 区：YOCO consumer SWA + 压缩边界累加器 ca_state/ica_state]。V4.1 只持久化前 20 层（编码器层）；消费层（解码器）的 SWA 靠 prefill 重算恢复，不存。压缩窗口边界天然对齐 128 token 存储粒度，无跨界依赖。
