通用大模型架构详解：一次前向的形状流转

拿一条真实请求（6 个 token）走完一个通用 decoder-only 大模型的全流程，每一步都标出具体形状

一句话概括：一个通用大模型 = Embedding 查表 + 32 层 decoder block（注意力 + FFN + 残差）+ 最终归一化 + LM head。整个前向传播里，主数据流的形状始终是 [1, 6, 4096]——进多少层都不变；只有入口（分词）和出口（LM head）改形状。
本篇的讲法：像 Kev 决策流程那篇一样，全程用一个具体例子走到底、全程写具体数字：输入是一条 6 个 token 的真实请求，隐藏维 4096、32 层、32 个注意力头（每头 128 维）、8 组 KV 头、FFN 中间层 11008、词表 152000——这些数字取自 Qwen / Llama 系主流开源模型的典型量级。B（batch）、S（序列长）、H（隐藏维）这些字母只在解释维度含义时出现。
[1, 6, 4096]

[1, 152000]

三个关键观察：

  • 入口和出口改形状，中间不改：tokenize 把文字变成 [6] 的整数序列，embedding 查表升到 [1, 6, 4096]；此后穿过全部 32 层形状不变，直到 LM head 投到 [1, 6, 152000]。残差流设计的直观体现——主干通道恒定宽度，子层只做"加工"，加工完加回主干。
  • 训练与解码的形状不同：训练时整段文本一次性进来（本例 [1, 6, 4096]），并行算所有 6 个位置；推理（生成）时用 KV Cache，每步只进 1 个新 token（[1, 1, 4096]），历史 6 个位置的结果都在缓存里。
  • LM head 是唯一接词表的投影：[4096, 152000] 的矩阵一次乘法就是约 37 亿次乘加（6 位置 × 4096 × 152000），长序列下是隐形开销大户。

1. 注意力部分：6 个 token 怎么互相看

步骤运算形状
Q 投影[1, 6, 4096] @ [4096, 4096][1, 6, 4096] → 拆头 [1, 32, 6, 128]
K / V 投影（GQA）[1, 6, 4096] @ [4096, 1024][1, 8, 6, 128]（只有 8 组头）
分数Q @ Kᵀ ÷ √128[1, 32, 6, 6]
掩码 + softmax因果掩码逐行归一化[1, 32, 6, 6]（6×6 的"谁能看谁"表）
加权求和probs @ V[1, 32, 6, 128]
合并多头32 头 × 128 → 4096[1, 6, 4096]

两个易混点：① [1, 32, 6, 128] 里的 32 是"头的维度"——6 个 token 各自被 32 个头分别表示成 128 维，和序列长度无关；② [1, 32, 6, 6] 的注意力分数是 6×6 的小方阵：第 i 行第 j 列表示"第 i 个 token 对第 j 个 token 的关注程度"，因果掩码把 j>i 的格子置 −∞（未来的内容不许看）。GQA 下 K/V 只有 8 组头，Q 的 32 个头每 4 个一组共用，分数矩阵依然是 [1, 32, 6, 6]，只是 K/V 存储省了 4 倍。

2. FFN 部分：升维、门控、降维

FFN 不做 token 之间的交互，只对每个位置独立"加深加工"：[1, 6, 4096] 先升到 [1, 6, 11008]（SwiGLU 有 gate / up 两份），SiLU(gate) × up 逐元素相乘后再降回 [1, 6, 4096]。参数量上 FFN 约占整层的三分之二，是大模型参数的主要存放地。

3. 残差连接：形状不变的秘密

每个子层的输出都会加回它的输入：output = x + sublayer(norm(x))。这就是主干形状恒为 [1, 6, 4096] 的原因——子层随便加工，主干始终保留原始信息通道。没有残差，32 层堆叠梯度根本传不回去。

四、解码阶段与 KV Cache：为什么长上下文贵

第 6 个位置采样出「是」之后开始自回归。每步只进 1 个新 token，但注意力需要"回看"全部历史，所以每层把历史 K/V 缓存下来：

  • 每层缓存的形状：K, V = [1, 8, S, 128]（S 是当前总长度，GQA 8 组头）；
  • 每 token 每层的 KV 元素数：2（K+V）× 8 头 × 128 维 = 2048 个元素；
  • fp16 存储（2 字节）→ 4KB / token / 层；32 层合计 128KB / token；
  • 本例 6 个 token 的前缀：6 × 128KB ≈ 768KB——很小；但 32K 上下文的请求：32,000 × 128KB ≈ 4GB，这就是长上下文贵的原因。
KV Cache 随序列长度线性增长、随 batch 倍增。站内另外两篇文章讲的正是压它的一套方案——DeepSeek-V4.1-Flash 推理加速解读（CED 层切分 + CSA2 跨层共享）与CED + CSA2 复现代码检视。

六、常见易混点

  • [1, 6, 4096] vs [1, 32, 6, 6]：前者是每个位置的表示（6 个位置 × 4096 维），后者是注意力分数（每头一张 6×6 的"谁看谁"表）。序列长了后者平方增长——32K 序列时是 [1, 32, 32768, 32768]，必须 FlashAttention / 稀疏注意力才能装下；
  • 拆头的两种写法：[1, 6, 4096] → [1, 32, 6, 128]（主流，先按头分组）或 [1, 6, 32, 128] 再转置，读源码时注意 permute / transpose 出现的位置；
  • 训练看 [1, 6, 152000]，推理只看 [1, 152000]：训练时 6 个位置的 logits 都要算 loss；生成时只关心最后一个位置；
  • Pre-Norm vs Post-Norm：现代模型几乎都是 Pre-Norm（先归一化再进子层），残差通道更干净、深层训练更稳；
  • 混合架构的差异：不是每层的"注意力"都是全注意力——如 Qwen3.5 系列大部分层是 Gated DeltaNet 线性注意力，只有少数层是全注意力，但"形状进出不变"的规律不变。
