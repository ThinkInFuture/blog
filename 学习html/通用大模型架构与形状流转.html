通用大模型架构详解：一次前向的形状流转

用特征维度的"形状语言"，把一个通用 decoder-only 大模型从文本到答案的完整链路讲清楚

一句话概括：一个通用大模型 = Embedding 查表 + N 层 decoder block（注意力 + FFN + 残差）+ 最终归一化 + LM head。整个前向传播里，主数据流的形状始终是 [batch, seq_len, hidden]，进多少层都不变——读懂了形状流转，就读懂了大模型的骨架。
[B, S, H]
主数据流形状：批大小 × 序列长 × 隐藏维
×N 层
decoder block 堆叠，形状进出不变
[B, S, V]
LM head 输出 logits，V 为词表大小

一、为什么要用"形状"来讲架构

读大模型源码或论文时，最容易迷路的地方不是数学，而是张量形状：一个 [B, S, H] 什么时候被拆成 [B, 头数, S, 头维]？logits 的 [B, S, V] 为什么采样时只看 [B, V]？KV Cache 到底缓存的是什么形状？这些问题搞不清，源码里每行矩阵乘法都像天书。

所以这篇基础篇用形状流转作为主线：从原始文本进模型，到下一个 token 出模型，每一步都标注张量的形状和每个维度的含义。文中用一个通用示意配置做参照（取自 Qwen / Llama 这类主流开源模型的典型量级，不同模型数值有差异，但结构完全一致）：

配置项通用示意值含义
词表大小 V≈ 152,000模型认识多少个 token
隐藏维 H4096每个 token 被表示成多少维向量（模型的"宽度"）
层数 N32decoder block 堆叠多少层（模型的"深度"）
注意力头数32 × 128 维多头注意力：32 个头，每头 128 维（32×128=4096=H）
KV 头数（GQA）8K/V 共享分组：8 组 KV 头服务 32 个 Q 头，省 KV Cache
FFN 中间维≈ 11008FFN 先升维再降维，中间层约 2.7×H（SwiGLU 门控）

记号约定：B = batch（一次同时处理几条请求），S = seq_len（序列长度），H = hidden_size，V = vocab_size。

图 1 · 通用大模型一次前向的八个阶段：主数据流形状 [B, S, H] 贯穿始终，只有入口（分词）和出口（LM head）改变形状

几个关键观察：

  • 入口和出口改形状，中间不改：tokenize 把文字变成 [S] 的整数序列，embedding 把它升到 [B, S, H]；此后穿过所有层形状都不变，直到最后的 LM head 把 [B, S, H] 投到 [B, S, V]。这就是"残差流"设计的直观体现——主干通道保持恒定宽度，每个子层只做"加工"，加工完加回主干。
  • 训练与解码的形状不同：训练时整段文本一次性进来（[B, S, H]，S 是全序列长），并行算所有位置；推理（生成）时用 KV Cache，每步只进 1 个新 token（[B, 1, H]），S 维只有缓存里的历史。
  • LM head 是唯一接词表的投影：[H, V] 的矩阵把 4096 维隐状态映射到 15 万个 token 的打分（logits），这一步计算量和显存都不小，是长序列推理的隐形开销之一。

1. 注意力部分：形状怎么变

注意力是唯一让 token 之间"互相看"的地方，也是形状变化最多的地方：

步骤运算形状
Q 投影[B, S, H] @ [H, H][B, S, H] → 拆头 [B, 32, S, 128]
K / V 投影（GQA）[B, S, H] @ [H, 1024][B, 8, S, 128]（只有 8 组头）
分数Q @ Kᵀ ÷ √128[B, 32, S, S]
掩码 + softmax逐行归一化[B, 32, S, S]（因果掩码后上三角为 0）
加权求和probs @ V[B, 32, S, 128]
合并多头32 × 128 → H[B, S, H]

两个易混点：① [B, 32, S, 128] 里的 32 是"头的维度"，和 S 没关系——每个头独立看完整序列，各自输出 128 维；② GQA 下 K/V 只有 8 组头，Q 的 32 个头分组共享同一组 K/V（每 4 个 Q 头共用 1 组），分数矩阵依然是 [B, 32, S, S]，只是 K/V 的存储省了 4 倍。

2. FFN 部分：升维、门控、降维

FFN（前馈网络）不和 token 之间交互，只对每个位置独立做"加深加工"：[B, S, H] 先升到 [B, S, 11008]，经过 SwiGLU 门控（两个矩阵一个过 SiLU 激活当"门"、一个当"值"，相乘），再降回 [B, S, H]。参数量上 FFN 约占整层的三分之二，是大模型参数的主要存放地。

3. 残差连接：形状不变的秘密

每个子层（注意力、FFN）的输出都会加回它的输入：output = x + sublayer(norm(x))。这就是主干形状恒为 [B, S, H] 的原因——子层可以随便加工，主干始终保留原始信息通道。没有残差，几十层堆叠梯度根本传不回去。

四、解码阶段与 KV Cache：为什么长上下文贵

生成阶段的每一步只处理 1 个新 token，但注意力需要"回看"所有历史位置。为避免重算，每层把历史 K/V 缓存下来：

  • 每层缓存的形状：K, V = [B, 8, S, 128]（GQA 8 组头）；
  • 每 token 每层的 KV 元素数：2（K+V）× 8 × 128 = 2048 个元素；
  • fp16 存储（2 字节）→ 4KB / token / 层；32 层合计 128KB / token；
  • 一条 32K 上下文的请求：32,000 × 128KB ≈ 4GB——仅仅是 KV Cache。
这就是长上下文贵的根源：KV Cache 随序列长度线性增长、随 batch 倍增。站内另外两篇文章讲的正是压它的一套方案——DeepSeek-V4.1-Flash 推理加速解读（CED 层切分 + CSA2 跨层共享）与CED + CSA2 复现代码检视。

六、常见易混点

  • [B, S, H] vs [B, S, S]：前者是每个位置的表示（3 维里 S 是"有多少个位置"），后者是注意力分数（S×S 是"每个位置看所有位置"）。长序列下 [B, 32, S, S] 的显存是平方增长的，这也是长序列要用 FlashAttention / 稀疏注意力的原因；
  • 拆头的两种写法：[B, S, H] → [B, 头数, S, 头维]（主流实现，先按头分组）或 [B, S, 头数, 头维] → 转置，读源码时注意 permute / transpose 出现的位置；
  • 训练看 [B, S, V]，推理只看 [B, V]：训练时 S 个位置的 logits 都要算 loss；生成时只关心最后一个位置的打分；
  • Pre-Norm vs Post-Norm：现代模型几乎都是 Pre-Norm（先归一化再进子层），残差通道更干净、深层训练更稳；
  • 混合架构的差异：不是每层的"注意力"都是全注意力——如 Qwen3.5 系列大部分层是 Gated DeltaNet 线性注意力，只有少数层是全注意力，但"形状进出不变"的规律不变。
